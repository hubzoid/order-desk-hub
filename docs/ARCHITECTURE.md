# Architecture

The desk is a Hubzoid hub: hub files plus two Python packages, `desk/` (the desk service) and `erp/` (the ERPNext module). It builds on Hubzoid's work items, write modes, operation ledger, stations, intake and approvals, and adds no second engine, queue or approval system.

## Pieces and who owns what

| Piece | Owner | What it does |
|---|---|---|
| Intake channels, sender trust, attachment storage | Hubzoid (SDK) | Email (DKIM), WhatsApp (signed webhooks, quarantine), and the hub's two synthetic sample channels feed `order_invoice_intake` work items |
| Work items, stages, retries, restarts | Hubzoid | Saved stages never run twice, a code change stops work for a person |
| `hub.operation.run`, write modes, approvals of operations | Hubzoid | Records the intent before a write, waits for the requester's approval of the exact digest in approve mode, turns a lost answer into `ambiguous` |
| HITL request cards in chat | Hubzoid | The chat approval card for `desk_approve_submission` (`ask: always`) |
| Stations | Hubzoid | `desk-extractor`: an isolated agent on `claude-local` with a JSON schema and no tools |
| Parsing, extraction checks, matching, validation, proposals | `desk/` | Deterministic, every value with its source and rule |
| Cases, claims, corrections, sender bindings, duplicate keys | `desk/` | One SQLite file in `.hubzoid/data/desk/`, compare-and-set on every change |
| ERP reads and the three-call write contract | `erp/` | Typed allowlisted reads, `create_draft`, `get`, `submit_approved` |

## The intake work item

`order_invoice_intake`, routes `triage` and `preview`, stages `parse`, `extract`, `match`:

1. **parse**: opens the case (one per source event, so a repeat delivery finds the same case), binds the party from the sender binding, reads every document into numbered elements (`E1`, `E2`, ...). Docling runs in a separate process for each PDF or image, with a deadline, one at a time.
2. **extract**: the station returns the typed `Extraction`. `desk.extract.verify` drops any value its cited element does not contain.
3. **match**: `desk.propose.build` matches and validates, then the case gets proposal revision 1 and its state.

It never writes to the ERP. Its requester is the workflow (unattended), or the person who released or uploaded the message.

## The case work item

`order_invoice_case`, requester = the case owner:

- **draft**: rechecks ownership, permission, state and the proposal digest, then `hub.operation.run("erp_create_draft", actions="erp.create_draft", recovery="reconcile")`. The adapter strips status fields, refuses identity and unknown fields, searches the business reference, writes with the unique operation marker, reads the draft back and compares it. Reconcile asks ERPNext for the marker: one document means applied, none means a resend is safe (the unique index forbids a second), more than one stops for a person.
- **submit**: approve mode only. `hub.operation.run("erp_submit", actions="erp.submit", target_version=...)` parks until the requester approves the exact content: company, document, party, reference, lines, totals, ERP version and approval digest. At dispatch Hubzoid rechecks the digest, the approver's access and the ERP version. `submit_approved` rereads with the submit credential, recomputes the approval digest, refuses an active ERPNext Workflow, posts exactly the reread document to `frappe.client.submit` (whose own `modified` check closes the race) and reads it back as docstatus 1.

## State and recovery

The case follows its work items (`Desk.sync`): a denial, a stopped item or an ambiguous operation shows on the case even if the process that caused it crashed. A crash after ERPNext saved a draft recovers through the operation's reconcile check to exactly one document (tested on the real engine).

## Data

- Hub files (versioned): policies, alias rows, unit words, sources, settings, write modes, the station, the connector file.
- Deployment data (`.hubzoid/`): Hubzoid's operational store (work items, operations, intake, files), the desk's store, the ERP module's state (applied configuration revisions, the sample backend's drafts).
- The dataset `distributor-v1` is generated byte for byte reproducibly and is never changed by a run.

## Later for the SDK

- `hubzoid intake import --synthetic`: the hub's sample loader stands in for it.
- A desk screen in the Console (queue with sources next to proposals): the Work Items and Intake screens plus the case page cover it today.
- Work-item operation approvals as native chat cards: the desk bridges them with an `ask: always` HITL tool.
- Hub-contributed CLI commands and API routes (`hubzoid desk ...`, `/api/hubs/{hub}/desk`): `hubzoid-desk` and the chat tools stand in.
